# MRQ002 `heading-punctuation`

Heading text ends with punctuation. Tags: `headings`, `mrq`. Off by default. Fixable.

A heading whose text ends with one of the `punctuation` characters is reported. It differs from [MD026](https://github.com/DavidAnson/markdownlint/blob/main/doc/md026.md) in what it reads: MD026 looks at the raw source of the heading line, MRQ002 at the text a reader sees.

- Punctuation inside inline markup counts: `# Done *now.*` and `# See [the docs!](…)` are reported, MD026 lets them pass because the line ends with `*` or `)`.
- Text that is not prose does not count: a heading that ends with inline code (`` # Call `run();` ``), math or an image (whose alt text is not shown) is fine.
- Trailing HTML comments, raw HTML and footnote references are looked past: `# Done. <!-- x -->` is reported.
- Entities count as the character they stand for (`&#33;` is `!`), where MD026 skips headings ending with an entity. GitHub emoji codes (`:smile:`) are left alone, as in MD026.

The default `punctuation` is MD026's (`.,;:!` and their full-width forms, not `?`), so switching between the two only changes how headings are read. Since MD026 is on by default, MRQ002 is off; turn MD026 off when you turn it on.

The fix deletes the punctuation and any whitespace before it, an escaping backslash (`\!`) included. Punctuation written as an entity is reported but not fixed.

## Options

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `punctuation` | string | `.,;:!。，；：！` | Characters a heading's text must not end with; empty turns the rule off |

## Examples

```markdown
# Reported.

## Also *reported.*

## Fine: `code;`

## Fine?
```

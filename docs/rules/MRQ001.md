# MRQ001 `valid-anchors`

Link to a missing anchor. Tags: `links`, `mrq`. Off by default. No fix.

The lint counterpart of `mrq validate`'s `missing-anchor` check, with the same link resolution and messages, so editors and `mrq lint` runs see it too. Unlike [MD051](https://github.com/DavidAnson/markdownlint/blob/main/doc/md051.md), which always computes GitHub slugs, anchors come from the document's flavor: its slugger (`-1` suffixes for gfm, `_1` for mkdocs), `{#id}` heading attributes (mkdocs), and Obsidian's case-insensitive heading names and `^block` ids. Turn MD051 off when you turn this rule on, or same-file links are reported twice.

What is checked:

- links and images to `#anchor`, reference links whose definition points at one, and wikilinks to `[[#heading]]` in the document itself;
- with `cross_file` (the default), links to `other.md#anchor`. The target is read from disk relative to the linting document (a leading `/` resolves from the current directory, as in `mrq validate`; documents from stdin resolve from the current directory too) and parsed with the linting document's flavor unless its frontmatter picks another.

What is not:

- targets that do not exist or are not Markdown files: missing files are `mrq validate`'s `missing-file`;
- wikilinks to other notes (`[[Note#Heading]]`): finding the note needs the vault-wide lookup that only `mrq validate` does;
- HTML `id` attributes, footnote anchors and GitHub line anchors (`#L10`), which are not anchors mrq knows about (the same gap as `mrq validate`).

Lint rules see one document at a time, so each linted document reads its link targets again; `mrq validate` shares them across a workspace.

## Options

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `cross_file` | boolean | `true` | Also check anchors in other Markdown files, read from disk |

## Examples

```markdown
# Intro

[fine](#intro) [reported](#outro) [reported if other.md has no "Usage" heading](other.md#usage)
```

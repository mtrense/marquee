# MRQ005 `no-url-wikilinks`

Bare URL in a wikilink. Tags: `links`, `url`, `mrq`. On by default. Fixable.

Obsidian takes whatever is between `[[` and `]]` for a note name, so `[[https://example.com]]` links to a note called `https://example.com` (created empty when clicked), not to the page. The same goes for embeds: `![[https://example.com/logo.png]]` shows nothing. Wikilinks and embeds whose target starts with `scheme://` or `www.` are reported. Only flavors with wikilinks (obsidian) have any, so the rule does nothing elsewhere; a bare URL outside a wikilink is [MD034](https://github.com/DavidAnson/markdownlint/blob/main/doc/md034.md)'s business.

The fix writes a Markdown link instead:

| Written | Fixed |
| --- | --- |
| `[[https://example.com/docs#install]]` | `<https://example.com/docs#install>` |
| `[[https://example.com/docs\|the docs]]` | `[the docs](https://example.com/docs)` |
| `![[https://example.com/logo.png\|Logo]]` | `![Logo](https://example.com/logo.png)` |
| `[[www.example.com]]` | `[www.example.com](https://www.example.com)` |
| `[[https://example.com/a b\|spaced]]` | `[spaced](<https://example.com/a b>)` |

An embed's alias becomes the alt text; Obsidian reads a size such as `100x200` there the same way. Targets with `<`, `>` or line breaks and aliases with brackets are reported but not fixed.

## Options

None.

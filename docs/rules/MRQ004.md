# MRQ004 `stale-include`

`mrq:include` region out of date. Tags: `directives`, `mrq`. On by default. Fixable.

An `mrq:include` region is the content between `<!-- mrq:include path="…" -->` and `<!-- mrq:end -->`, which `mrq interpolate --in-place` regenerates. The region is stale when that content differs from what `--in-place` writes: the included content (with heading shifts, `section` and `select` filters, dedent and link rewriting applied), framed by blank lines and indented for the region's container. The fix writes that content, as `mrq interpolate --in-place` does.

- `path` resolves as in `mrq validate`: relative to the document, or from the current directory for a leading `/` and for stdin. Included files are parsed with the default options.
- Regions whose include fails somewhere are skipped: a missing file, a cycle, a bad attribute, a `section` or `select` that finds nothing, or a failing include in an included file. `mrq validate` and `mrq interpolate` report why.
- Remote `http(s)` includes are skipped, also inside included files: linting never fetches anything.
- A bare start marker without `mrq:end` is not stale: `mrq interpolate` expands it when writing to stdout, and only `--in-place` adds the end marker. (`mrq interpolate --check` does report it.)

## Options

None.

## Examples

```markdown
<!-- mrq:include path="chapters/install.md" -->
<!-- mrq:end -->
```

is reported if `chapters/install.md` has content, and fixed to

```markdown
<!-- mrq:include path="chapters/install.md" -->

# Install

…

<!-- mrq:end -->
```

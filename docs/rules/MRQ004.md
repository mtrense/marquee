# MRQ004 `stale-include`

`mrq:include` region out of date. Tags: `directives`, `mrq`. On by default. No fix yet.

An `mrq:include` region is the content between `<!-- mrq:include path="…" -->` and `<!-- mrq:end -->`, which `mrq interpolate --in-place` regenerates. The region is stale when that content differs from what the include expands to.

Expanding an include (heading shifts, `section` and `select` filters, dedent, link rewriting) needs the include resolver, which is not implemented yet. Until it is, the rule reports only regions that are stale for certain without expanding them: an empty region (nothing but whitespace between the markers) whose file has a body after its frontmatter, when no attribute could make the expansion empty.

- Only regions whose attributes are all among `path`, `shift`, `dedent`, `frontmatter`, `lang` and `sha256` are checked. `section`, `select`, `lines`, symbol attributes (`function`, …) and unknown attributes can select nothing, so such regions are skipped.
- `path` resolves as in `mrq validate`: relative to the document, or from the current directory for a leading `/` and for stdin. Missing files (`mrq validate` reports `missing-include`) and remote `http(s)` paths are skipped.
- A bare start marker without `mrq:end` is not stale: `mrq interpolate` expands it when writing to stdout, and only `--in-place` adds the end marker.
- A region with content is not compared with its file yet, so outdated content goes unreported.

Once the resolver exists, every region's content will be compared with its expansion, and the fix will replace the content, as `mrq interpolate --in-place` does.

## Options

None.

## Examples

```markdown
<!-- mrq:include path="chapters/install.md" -->
<!-- mrq:end -->
```

is reported if `chapters/install.md` has content.

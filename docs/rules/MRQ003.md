# MRQ003 `frontmatter-key-order`

Frontmatter keys out of order. Tags: `frontmatter`, `mrq`. Off by default. Fixable for YAML.

Top-level frontmatter keys listed in `order` come first, in that order. The keys not listed follow, sorted by name with `alphabetical` (ignoring case first, then by case), otherwise in any order. Each key that should come before the key above it is reported. Nested keys are not checked, and malformed frontmatter (reported by `mrq validate`) is skipped.

In TOML, tables declared with a header (`[extra]`) must come after the other top-level keys, so the two groups are ordered separately: the keys before the first header among themselves, the tables among themselves.

With neither option set the rule has nothing to check, so it is off by default. Configuring it with options turns it on.

The fix, attached to the first finding, sorts a YAML block mapping whose keys all start their lines. Each key moves with its value, the lines up to the next key and the comment lines (starting at column 0) right above it; comments above the first key stay at the top. TOML frontmatter and YAML flow mappings (`{b: 1, a: 2}`) are reported but not fixed.

## Options

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `order` | list of strings | `[]` | Keys that come first, in this order |
| `alphabetical` | boolean | `false` | Sort the keys not in `order` by name |

## Examples

With `{ order: [title, date], alphabetical: true }`:

```yaml
---
date: 2026-10-31
title: Notes       # reported: should come before `date`
tags: [a]
draft: false       # reported: should come before `tags`
---
```
